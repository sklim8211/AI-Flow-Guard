# AISidecar 론칭 전 종합 테스트 시나리오

> 이 문서는 **"우리 서비스가 약속한 가치를 실제로 전달하는가"**를 사용자 입장에서 검증합니다.
> 코드 테스트가 아니라 **사용자 여정 테스트**예요. 한 시나리오 = 한 명의 사용자가 한 가지 목표를 달성하는 흐름.

---

## 테스트가 검증하려는 우리 서비스의 7가지 핵심 측면

각 시나리오는 다음 중 하나 이상을 확인합니다:

| # | 측면 | 한 줄 설명 |
|---|------|---------|
| **P1** | **AI 비연결 원칙** | 우리가 AI를 안 부르고, 사용자 컨텍스트를 보지 않는다 |
| **P2** | **표준 프롬프트의 정확성** | 각 아이콘이 약속한 텍스트를 정확히 카피한다 |
| **P3** | **메타 기반 자동 분류** | AI 답변이 알맞은 폴더/이름으로 들어간다 — 우리 서비스의 핵심 가치 |
| **P4** | **워크플로별 적합성** | 작가에겐 작가다운 질문, 개발자에겐 개발자다운 질문 |
| **P5** | **데이터 안전** | 실수로 덮어쓰지 않고, 로컬 폴더와 동기화가 어긋나지 않는다 |
| **P6** | **로컬 우선 / 프라이버시** | 모든 데이터가 사용자 브라우저·디스크에만 존재 |
| **P7** | **사용 마찰 최소화** | 평범한 사용자가 헤매지 않고 한 사이클을 끝낼 수 있다 |

---

## 사전 준비

- **브라우저**: Chrome 또는 Edge (File System Access API 필요)
- **AI 도구**: ChatGPT 또는 Claude (유료 모델 권장 — 무료 모델은 양식 지시를 덜 따름)
- **빈 폴더**: 디스크에 테스트용 폴더 하나 만들어두기 (예: `~/Documents/qq-test`)
- **개발자 도구**: F12로 콘솔 열어두기 (에러 감지용)
- **소요 시간**: 전체 약 60~90분

---

# 시나리오 1 — 첫 사용자 여정 (10분)

**확인 측면**: P7 (사용 마찰 최소화)
**왜 중요한가**: 첫 1분 안에 헤매면 사용자는 떠납니다. 안내 없이 무엇을 해야 할지 직관적으로 알 수 있어야 합니다.

### 단계

1. 브라우저에서 앱 첫 진입 (시크릿 창 권장 — localStorage 깨끗)
2. 온보딩 화면 확인
3. "시작하기" 또는 첫 프로젝트 생성 흐름 따라가기
4. 워크플로 5종(개발/글쓰기/리서치/디자인/전략) 중 하나 선택
5. "오늘" 탭 자동 진입 확인

### 기대 결과 / 점검 항목

- [ ] 온보딩이 한국어로 친절하게 표시됨
- [ ] "AI 응답은 자동 저장되지 않습니다" 같은 비연결 원칙이 어딘가에서 명시됨
- [ ] 워크플로 선택 후 사이드바 아이콘이 표시됨
- [ ] **"오늘" 탭에 빈 상태일 때 무엇을 해야 할지 안내가 있는가** (없으면 → 첫 사용자가 막힘)
- [ ] 콘솔에 에러 없음

### 합격 기준
다른 사람에게 앱 URL을 주고 1분 안에 "첫 프롬프트를 카피할 준비"가 될 수 있어야 합니다.

---

# 시나리오 2 — 표준 프롬프트 7개 카피 검증 (15분)

**확인 측면**: P2 (표준 프롬프트의 정확성), P4 (워크플로별 적합성)
**왜 중요한가**: 모든 가치는 "잘 짜인 프롬프트가 정확히 전달되는 것"에서 시작합니다. 여기가 깨지면 다음 단계는 무의미합니다.

### 단계

워크플로를 **"글쓰기"**로 설정한 상태에서:

1. Resume 아이콘 클릭 → 활성 프롬프트 패널이 뜨는지 확인 → 카피 버튼 클릭 → 메모장에 붙여넣기
2. Summary 아이콘으로 동일 반복
3. Anchors, Next, Compress, Backup, Restore 각각 반복
4. 워크플로를 **"개발"**로 바꾸고 → Resume·Summary·Anchors·Next 다시 카피해 비교

### 기대 결과 / 점검 항목

- [ ] 7개 아이콘 모두 카피가 작동
- [ ] 패널에 표시되는 프롬프트 텍스트와 실제 카피된 텍스트가 동일
- [ ] Resume/Summary/Anchors/Next는 워크플로 변경 시 본문이 달라짐
  - 글쓰기 Resume: `CURRENT NARRATIVE`, `TONE & THEMES` 포함
  - 개발 Resume: `ARCHITECTURE STATE`, `BLOCKERS` 포함
- [ ] Compress/Backup/Restore는 워크플로 무관하게 동일
- [ ] 모든 프롬프트(Restore 제외)가 YAML 메타 헤더 지시문을 포함
- [ ] 모든 프롬프트(Restore 제외)가 `filename: ...` 줄 지시문을 포함
- [ ] **슬러그 가이드 금지어(notes/update/summary 등)가 명시되어 있음**

### 합격 기준
7개 × 5개 워크플로 = 사실상 모든 분기 변형이 정상이며, 출력 텍스트에 깨진 변수나 누락이 없습니다.

# 시나리오 3 — AI와 실제 한 사이클 (Summary 기준) (10분)

**확인 측면**: P3 (메타 기반 자동 분류) — **서비스의 핵심 가치**
**왜 중요한가**: 이 한 사이클이 우리 서비스의 핵심 약속입니다. 여기가 어색하면 전부 무너집니다.

### 단계

1. ChatGPT/Claude를 열어 짧은 대화 하나 만들기 (예: "Express 미들웨어 순서 결정에 대해 30초만 이야기하자")
2. 5~10 메시지 정도 주고받기
3. AISidecar에서 **개발 워크플로**의 **Summary** 아이콘 클릭 → 카피
4. AI 대화창에 붙여넣기 → 답변 받기
5. AI 답변 전체를 카피
6. AISidecar의 **📋 클립보드에서 저장** 아이콘 클릭
7. 저장 모달 확인

### 기대 결과 / 점검 항목

- [ ] AI 답변에 YAML 메타 헤더가 정상 포함됨 (없으면 → AI 모델 문제, 다른 모델로 재시도)
- [ ] AI 답변에 `filename: summary_xxx.md` 줄이 정상 포함됨
- [ ] **저장 모달에 "✨ 자동 인식됨" 배지가 뜸**
- [ ] 폴더가 자동으로 **SUMMARIES**로 선택됨
- [ ] 파일명에 의미 있는 슬러그가 들어감 (예: `summary_express-middleware-order.md`)
  - **금지어("notes", "session", "today")가 안 들어갔는지 확인** — 들어갔으면 슬러그 가이드 강화가 약함
- [ ] [저장] 누르면 모달 닫히고 Workspace 탭의 SUMMARIES 폴더에 파일 생성됨
- [ ] 파일을 열어보면 메타 헤더 + 본문이 그대로 보존됨

### 합격 기준
**사용자가 폴더나 파일명을 한 글자도 안 건드리고 저장이 끝납니다.** 이게 우리 서비스의 마법이에요.

### 흔한 실패 시그널
- 자동 인식 안 됨 → AI가 양식을 안 지킨 것. 다른 모델로 재시도, 그래도 안 되면 양식 지시문 보강 필요
- 파일명이 `summary_notes.md` 같은 일반 단어 → 금지어 가이드가 약함

# 시나리오 4 — 5개 워크플로 × Resume 적합성 (15분)

**확인 측면**: P4 (워크플로별 적합성)
**왜 중요한가**: 워크플로 분기를 만든 이유는 작가에겐 작가다운 답을, 개발자에겐 개발자다운 답을 받기 위함입니다. 분기가 의미 있는지 검증합니다.

### 단계

각 워크플로마다 동일한 일을 합니다:

1. 해당 워크플로의 가상 대화를 AI와 만듦 (예: 글쓰기면 단편 소설 토론, 리서치면 가설 검증)
2. Resume 아이콘 → 카피 → AI에 붙여넣기 → 답변 받기
3. 답변의 본문 구조 확인

### 기대 결과 / 점검 항목

| 워크플로 | 본문에 나타나야 할 항목 |
|---------|-------------------|
| 개발 | CURRENT, ARCHITECTURE STATE, BLOCKERS |
| 글쓰기 | CURRENT NARRATIVE, TONE & THEMES, OPEN THREADS |
| 리서치 | CURRENT HYPOTHESIS, RECENT FINDINGS, OPEN QUESTIONS |
| 디자인 | CURRENT DIRECTION, UX GOALS, OPEN UX PROBLEMS |
| 전략 | KEY ASSUMPTIONS, OPEN RISKS, NEXT STRATEGIC STEP |

- [ ] 5개 워크플로 모두 본문 구조가 해당 분야에 맞음
- [ ] 답변 내용이 분야에 맞는 어휘로 채워짐 (개발 워크플로에서 "감정 방향" 같은 글쓰기 어휘가 안 튀어나옴)
- [ ] 각 답변이 알맞은 폴더(CURRENT)로 자동 분류됨

### 합격 기준
워크플로를 바꾼 가치가 실제 결과물에서 느껴집니다. "이거 그냥 라벨만 다른 거 아니야?"가 아니라야 합니다.

---

# 시나리오 5 — Backup → 수정 → Restore 안전망 흐름 (10분)

**확인 측면**: P3 (자동 분류), P5 (데이터 안전)
**왜 중요한가**: Backup/Restore는 "큰 수정을 무서워하지 않게 만든다"는 약속입니다. 실제로 안전망 역할을 하는지 검증.

### 단계

1. AI와 작업 중인 상태 가정 (시나리오 3의 대화 이어서)
2. **Backup** 아이콘 → 카피 → AI에 붙임 → 답변 받기
3. 답변 카피 → 📋 저장
4. SAFE 폴더에 `backup_v1_xxx.md` 형식으로 들어갔는지 확인
5. **두 번째 Backup**도 같은 흐름으로 만들기 → `backup_v2_xxx.md`가 되는지 확인 (버전 자동 증가)
6. **Restore** 아이콘 → 카피
7. Workspace에서 backup_v1 파일 열어 내용 카피
8. AI에 Restore 프롬프트 붙이고, 끝에 백업 내용 붙임 → 답변 받기
9. AI가 백업 시점의 상태를 재구성해 설명하는지 확인

### 기대 결과 / 점검 항목

- [ ] Backup 결과에 `version`, `risk_level`, `restoration_hint`, `changes_from_previous` 필드가 있음
- [ ] 두 번째 Backup 시 AI가 `v2`로 올림 (이전 백업이 같은 대화에 있어야 함)
- [ ] SAFE 폴더에 둘 다 별개 파일로 저장됨
- [ ] **백업 파일명이 `backup_v[N]_의미있는-슬러그.md` 형식** (예: `backup_v1_before-middleware-refactor.md`)
- [ ] Restore 답변이 "이건 v1, 위험도는 OO, 복원 시 주의할 점은 OO" 형식으로 옴
- [ ] Restore 답변에는 메타 헤더가 없음 (Restore는 결과물에 메타를 요구하지 않는 입력 프롬프트라서)

### 합격 기준
사용자가 "이제 큰 수정 들어가도 돌아갈 수 있다"는 심리적 안전감을 갖게 됩니다.

---

# 시나리오 6 — 같은 이름 저장 충돌 (5분)

**확인 측면**: P5 (데이터 안전)
**왜 중요한가**: 실수로 중요한 백업·요약을 덮어쓰면 데이터 손실입니다. 안전한 기본값이 작동해야 합니다.

### 단계

1. SUMMARIES 폴더에 이미 파일이 하나 있는 상태 (시나리오 3 결과 사용)
2. AI에게 비슷한 Summary를 하나 더 요청 → 답변 받기
3. AI가 같은 슬러그를 생성하도록 답변 수정 (예: `filename:` 줄을 직전과 동일하게)
4. 📋 저장 → 저장 모달 열기

### 기대 결과 / 점검 항목

- [ ] **노란 경고 박스가 표시됨** ("같은 이름의 파일이 이미 있어요" 류)
- [ ] 라디오 두 개: "새로 만들기 (_2 자동 붙임)" / "덮어쓰기"
- [ ] **기본 선택이 "새로 만들기"** (안전 우선)
- [ ] "새로 만들기" 상태로 저장 → `xxx_2.md` 형식으로 별개 파일 생성
- [ ] (선택) "덮어쓰기" 시도 → 동일 파일이 갱신되는지 확인

### 합격 기준
사용자가 실수해도 데이터가 사라지지 않습니다.

---

# 시나리오 7 — 로컬 폴더 연결 + 디스크 동기화 (10분)

**확인 측면**: P5 (데이터 안전), P6 (로컬 우선)
**왜 중요한가**: 브라우저 캐시가 날아가도 디스크 폴더는 살아있어야 합니다. 두 저장소가 어긋나지 않아야 합니다.

### 단계

1. Workspace 탭 → 폴더 연결 버튼
2. 사전 준비한 빈 디스크 폴더(`~/Documents/qq-test`) 선택 → 권한 부여
3. 기존에 저장된 파일들이 디스크 폴더에 미러링되는지 확인
4. 시나리오 3을 한 번 더 돌려서 새 파일 저장 → 디스크 폴더에도 즉시 생성되는지 확인
5. **디스크 폴더에서 파일 하나를 OS 파일 탐색기로 열어 내용 확인**
6. **앱에서 그 파일을 삭제** → 디스크에서도 사라지는지 확인
7. 브라우저 닫고 다시 열기 → 폴더 권한 재요청 시 정상 재연결되는지

### 기대 결과 / 점검 항목

- [ ] 폴더 권한 요청 다이얼로그가 정상 표시
- [ ] 새 저장이 localStorage + 디스크 양쪽에 동기화됨
- [ ] 디스크 파일이 사람이 읽을 수 있는 마크다운(.md)임 (이진 포맷 아님)
- [ ] 앱에서 삭제 시 디스크에서도 삭제됨
- [ ] **Firefox/Safari에서 진입 시 "지원되지 않습니다" 안내가 명확하게 표시됨** (없으면 다른 브라우저 사용자가 막힘)

### 합격 기준
브라우저를 신뢰하지 않는 사용자도 "디스크에 내 파일이 그대로 있다"는 확신을 가질 수 있습니다.

---

# 시나리오 8 — Consolidate (10분)

**확인 측면**: P3 (자동 분류), P7 (사용 마찰)
**왜 중요한가**: Consolidate는 "파일이 쌓여도 정리 가능"이라는 약속입니다. 마지막 신규 기능이라 안정성이 중요합니다.

### 단계

1. SUMMARIES 폴더에 같은 주제의 파일 3개가 있는 상태 만들기 (없으면 시나리오 3 반복)
2. Workspace 탭 → 우측 위 "선택" 토글 켜기
3. 파일 옆 체크박스로 3개 선택
4. 하단 "🗂 3개 합치기 → AI 프롬프트 만들기" 버튼 클릭
5. 활성 프롬프트 패널이 열리고, 안에 3개 파일 내용이 첨부된 프롬프트가 표시되는지 확인
6. 카피 → AI에 붙임 → 답변 받기
7. 답변을 📋로 저장

### 기대 결과 / 점검 항목

- [ ] "선택" 토글 시 체크박스가 표시되고 선택된 파일 행 배경색이 바뀜
- [ ] 1개만 선택했을 때는 합치기 버튼이 **비활성** + "2개 이상 선택하세요" 안내
- [ ] 합치기 버튼 클릭 후 선택 모드가 자동으로 해제됨
- [ ] 프롬프트 안에 `===== FILE 1: xxx =====` 형식으로 원본 내용이 첨부됨
- [ ] AI 답변에 **`consolidated_from`** 필드가 있고, 합친 원본 파일명이 나열됨
- [ ] 답변이 알맞은 폴더로 자동 분류됨 (kind 따라)
- [ ] **원본 3개는 그대로 살아있음** (자동 삭제 X)

### 합격 기준
파일이 쌓여도 사용자가 정리할 수 있는 길이 있고, 원본을 잃을 위험은 없습니다.

# 시나리오 9 — 워크플로 필터 (Today 탭) (5분)

**확인 측면**: P4 (워크플로별 적합성), P7 (사용 마찰)
**왜 중요한가**: 한 프로젝트에 글쓰기·개발 파일이 섞이면 혼란. 활성 워크플로에 맞는 파일만 보여야 합니다.

### 단계

1. 글쓰기 워크플로로 파일 2개 저장 (시나리오 3 방식)
2. 같은 프로젝트의 워크플로를 "개발"로 변경
3. "오늘" 탭 확인

### 기대 결과 / 점검 항목

- [ ] 글쓰기 파일들이 Today 탭에서 **숨겨짐**
- [ ] **숨김 개수 배너**가 표시됨 ("N개가 다른 워크플로라 숨겨졌어요" 류)
- [ ] 배너에 "Workspace로 이동" 버튼이 있고 작동함
- [ ] Workspace 탭에서는 모든 파일이 보임 (필터 안 됨)
- [ ] common 워크플로(Compress/Backup/Restore 결과) 파일은 어느 워크플로에서도 보이고 🛟 배지 표시

### 합격 기준
한 프로젝트를 여러 용도로 써도 컨텍스트가 섞이지 않습니다.

# 시나리오 10 — PWA 설치 + 사이드패널 모드 (5분)

**확인 측면**: P7 (사용 마찰), P1 (AI 비연결 — 우리 앱이 AI 옆에 떠 있는 도우미라는 정체성)
**왜 중요한가**: 이 앱의 매력 중 하나는 "ChatGPT 옆에 항상 떠 있는 작은 창"입니다. PWA가 작동해야 그 가치를 줍니다.

### 단계

1. Chrome 주소창 옆 **설치 아이콘** 또는 앱의 "Install" 버튼 (조건부 노출) 클릭
2. 설치 → 데스크톱 앱처럼 별창으로 열림
3. 별창의 너비를 좁혀보기 (≤440px)
4. ChatGPT 창 옆에 나란히 배치

### 기대 결과 / 점검 항목

- [ ] 설치 버튼이 미설치 상태에서만 노출되고 설치 후 사라짐
- [ ] 별창 모드 아이콘이 PWA 매니페스트의 것으로 표시됨
- [ ] 좁혀도 UI가 깨지지 않고 사이드패널 모드로 전환됨
- [ ] 오프라인 상태에서도 앱이 열림 (서비스 워커 작동 확인)
- [ ] ChatGPT 옆에 띄워두고 한 사이클(시나리오 3) 돌리는 동선이 자연스러운지

### 합격 기준
"매일 띄워두고 싶다"는 인상을 줍니다.

# 시나리오 11 — 저장 알림 토스트 (10분, 또는 시간 단축 테스트)

**확인 측면**: P7 (사용 마찰)
**왜 중요한가**: "오래 작업했는데 저장을 잊는" 패턴을 막아주는 안전망입니다.

### 단계 (정상 테스트는 1시간 대기)

1. 앱 열고 아무 작업도 하지 않음 (copy/save/edit 하지 말 것)
2. 1시간 대기 → 토스트가 화면 하단에 나타나는지 확인
3. [지금 저장] / [1시간 뒤] / X 버튼 작동 확인

### 시간 단축 테스트 (개발자 도구로)

- 콘솔에서 localStorage의 `qq_last_activity` 값을 1시간 전으로 조작
- 또는 코드에서 임시로 임계값을 1분으로 낮춰서 확인

### 기대 결과 / 점검 항목

- [ ] 토스트가 1시간 무활동 후 자동 표시됨
- [ ] 모달·온보딩·활성 프롬프트가 열려있을 땐 **표시 안 됨** (방해 안 함)
- [ ] [지금 저장] → 저장 모달이 열림
- [ ] [1시간 뒤] → 토스트 닫히고 다음 1시간 카운터 시작
- [ ] copy/save/edit 직후엔 토스트가 안 뜸 (활동 갱신이 작동)

### 합격 기준
잔소리하지 않으면서 필요한 순간에만 살짝 알려줍니다.

# 시나리오 13 — 프라이버시·비연결 원칙 검증 (5분)

# 시나리오 14 — 에러 / 엣지 케이스 (10분)

**왜 중요한가**: 정상 흐름은 다들 통과합니다. 진짜 품질은 깨졌을 때 드러나요.

### 단계 및 점검 항목

| 케이스 | 기대 동작 |
|-------|---------|
